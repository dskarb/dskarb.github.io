Narzędzia deweloperskie AI

AI Engineer sam intensywnie korzysta z AI przy pisaniu kodu. Jakie są kategorie narzędzi i jak pracować z nimi efektywnie, a nie tylko szybko.

autouzupełnianie vs agencipliki kontekstuworkflow z agentemryzyka
TL;DR Agent kodujący jest tak dobry, jak kontekst i pętla informacji zwrotnej, które mu dasz: jasne zadanie, plik z konwencjami projektu, testy i typy, które może uruchomić, oraz Twój review każdej zmiany.

Kategorie narzędzi

⌨️ Autouzupełnianie

Podpowiedzi w edytorze podczas pisania (np. GitHub Copilot). Szybkie, lokalny kontekst pliku. Dobre do boilerplate'u.

💬 Czat w IDE

Pytania o kod, wyjaśnienia, refaktor zaznaczonego fragmentu. Cursor, VS Code + Copilot Chat, JetBrains AI, Windsurf.

🤖 Agenci kodujący

Samodzielnie czytają repo, edytują wiele plików, uruchamiają testy i komendy. Claude Code, Codex, Gemini CLI, tryby agentowe w IDE.

☁️ Agenci w tle

Zadanie z issue → agent pracuje w chmurze → otwiera pull request do review. Dobre do dobrze zdefiniowanych, niezależnych zadań.

🔍 Review i bezpieczeństwo

Automatyczne code review PR-ów, wykrywanie podatności, generowanie testów.

🧪 Playgroundy i konsole

Panele dostawców do testowania promptów, parametrów i narzędzi przed napisaniem kodu.

Plik kontekstu projektu

Większość agentów czyta plik z instrukcjami w katalogu głównym repozytorium (np. CLAUDE.md, AGENTS.md lub reguły w konfiguracji IDE). To system prompt dla Twojego projektu — oszczędza powtarzania tych samych uwag.

# Projekt: panel sklepu (Next.js 15, TypeScript, Supabase) ## Komendy - `npm run dev` — serwer deweloperski - `npm test` — testy (Vitest); uruchom po każdej zmianie logiki - `npm run typecheck` — musi przechodzić przed commitem ## Konwencje - Komponenty serwerowe domyślnie; "use client" tylko gdy potrzebny stan/efekty - Walidacja wejścia API przez Zod w `src/lib/schemas.ts` - Wywołania LLM wyłącznie przez `src/ai/client.ts` (retry, tracing, limity) - Prompty w `prompts/*.md`, nie w kodzie ## Nie rób - Nie modyfikuj plików w `src/generated/` — są generowane z bazy - Nie dodawaj zależności bez pytania

Efektywny workflow z agentem

Od zadania do merge
1. kontekstOpisz cel, ograniczenia i kryteria akceptacji. Wskaż pliki-przykłady („zrób jak w OrdersTable.tsx”).
2. planPrzy większych zmianach poproś najpierw o plan bez edycji. Popraw plan — to tańsze niż poprawianie kodu.
3. małe krokiRealizacja etapami. Każdy etap kończy się działającym stanem i commitem.
4. weryfikacjaAgent uruchamia testy, typecheck, linter. Testy napisane przed implementacją to najlepszy sygnał „gotowe”.
5. reviewCzytasz diff jak PR od kolegi. Odpowiadasz za każdą linijkę, którą mergujesz.
dodaj eksport do csv
Dodaj przycisk „Eksport CSV” w OrdersTable.tsx. Eksportuje aktualnie przefiltrowane zamówienia (kolumny jak w tabeli, separator ;, UTF-8 z BOM dla Excela). Logika w src/lib/csv.ts + testy jednostkowe dla polskich znaków i średników w treści. Bez nowych zależności.

Ryzyka i dobre praktyki

  • Sekrety: pliki .env poza zasięgiem agenta lub wykluczone; nie wklejaj kluczy do czatu.
  • Uprawnienia: agent pyta o zgodę przed komendami destrukcyjnymi; nie uruchamiaj w trybie „zezwól na wszystko” na produkcyjnych danych.
  • Zmyślone API: agent może użyć nieistniejącej funkcji biblioteki lub nieaktualnej wersji API — typy i testy to wyłapią.
  • Zależności: sprawdzaj każdą nową paczkę (literówki w nazwach to wektor ataku supply chain).
  • Rozumienie: jeśli nie potrafisz wyjaśnić kodu na review, nie merguj go.
  • Polityka firmy: sprawdź, które narzędzia i z jakimi ustawieniami prywatności są dozwolone dla kodu klienta.
Jak to łączy się z resztą kompendiumAgenci kodujący to dokładnie ta architektura z modułu 11 (pętla + narzędzia: odczyt plików, edycja, terminal), często z serwerami MCP z modułu 12 i plikami kontekstu z modułu 05. Obserwując, jak działają, uczysz się projektować własnych agentów.

🧪 Ćwiczenia praktyczne

Ćwiczenie z agentem kodującym: weź dowolne zadanie z kodem z tego kompendium, skopiuj treść i testy do swojego repo i rozwiąż je z agentem (Claude Code, Codex, Cursor). Porównaj: ile iteracji potrzebował, czy uruchamiał testy, czy jego rozwiązanie jest czytelniejsze od Twojego. Potem zrób to samo z dobrym plikiem CLAUDE.md/AGENTS.md i porównaj wynik.
