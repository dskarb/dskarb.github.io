Rozmowa wieloturowa — Ty trzymasz stan

import Anthropic from "@anthropic-ai/sdk"; import * as readline from "node:readline/promises"; const client = new Anthropic(); const history: Anthropic.MessageParam[] = []; const rl = readline.createInterface({ input: process.stdin, output: process.stdout }); while (true) { const text = await rl.question("Ty: "); if (text === "exit") break; history.push({ role: "user", content: text }); const res = await client.messages.create({ model: "claude-haiku-5-5", max_tokens: 800, system: "Jesteś pomocnym asystentem.", messages: history, // CAŁA historia przy każdym wywołaniu }); const answer = res.content.filter(b => b.type === "text").map(b => b.text).join(""); history.push({ role: "assistant", content: answer }); console.log("AI:", answer, `\n[in: ${res.usage.input_tokens}, out: ${res.usage.output_tokens}]`); } rl.close();

Uruchom to i obserwuj input_tokens — rośnie z każdą turą. To jest powód, dla którego długie rozmowy są drogie i trzeba nimi zarządzać (streszczanie, przycinanie, prompt caching).

Structured output — JSON zamiast prozy

W aplikacjach rzadko chcesz luźny tekst. Chcesz obiekt, który zapiszesz w bazie lub wyświetlisz w UI. Trzy poziomy niezawodności:

1. Prośba w prompcie

„Zwróć JSON o polach…”. Działa często, ale nie zawsze (dodatkowy tekst, brakujące pola).

zawodne

2. Wymuszone narzędzie

Definiujesz narzędzie z JSON Schema i wymuszasz jego użycie. Model zwraca argumenty zgodne ze schematem.

dobre

3. Constrained decoding

Tryb „structured outputs / strict” — dostawca ogranicza sampling do tokenów zgodnych ze schematem.

najlepsze

Niezależnie od metody zawsze waliduj wynik (np. Zodem) — schemat gwarantuje składnię, nie sensowność wartości.

import Anthropic from "@anthropic-ai/sdk"; import { z } from "zod"; const client = new Anthropic(); const Invoice = z.object({ vendor: z.string(), nip: z.string().regex(/^\d{10}$/).nullable(), issueDate: z.string().describe("YYYY-MM-DD"), totalGross: z.number(), currency: z.enum(["PLN", "EUR", "USD"]), items: z.array(z.object({ name: z.string(), qty: z.number(), unitNet: z.number() })), }); // zod v4: schemat Zod → JSON Schema (usuwamy meta-pole $schema) const { $schema, ...invoiceSchema } = z.toJSONSchema(Invoice); const tool: Anthropic.Tool = { name: "save_invoice", description: "Zapisuje dane wyciągnięte z faktury.", input_schema: invoiceSchema as Anthropic.Tool.InputSchema, }; export async function extractInvoice(text: string) { const res = await client.messages.create({ model: "claude-haiku-5-5", max_tokens: 2000, tools: [tool], tool_choice: { type: "tool", name: "save_invoice" }, // wymuszenie messages: [{ role: "user", content: `Wyciągnij dane z faktury. Brak danej = null.\n\n\n${text}\n` }], }); const call = res.content.find(b => b.type === "tool_use"); if (!call) throw new Error("Model nie zwrócił danych"); return Invoice.parse(call.input); // walidacja — rzuci, jeśli coś się nie zgadza } import OpenAI from "openai"; const client = new OpenAI(); const res = await client.responses.create({ model: "gpt-5.4-mini", input: "Wyciągnij nazwę i kwotę: 'Faktura od ACME na 1230,50 zł'", text: { format: { type: "json_schema", name: "invoice", strict: true, // constrained decoding schema: { type: "object", properties: { vendor: { type: "string" }, amount: { type: "number" } }, required: ["vendor", "amount"], additionalProperties: false, }, }, }, }); const data = JSON.parse(res.output_text); // nadal waliduj przed użyciem

// Oficjalne SDK mają wbudowany retry: new Anthropic({ maxRetries: 3, timeout: 60_000 }) // Gdy budujesz własny (np. fallback między dostawcami): export async function withRetry(fn: () => Promise, tries = 4): Promise { for (let attempt = 0; ; attempt++) { try { return await fn(); } catch (err: any) { const status = err?.status as number | undefined; const retryable = status === 429 || (status !== undefined && status >= 500); if (!retryable || attempt >= tries - 1) throw err; const base = 500 * 2 ** attempt; // 0.5s, 1s, 2s, 4s const delay = base / 2 + Math.random() * base; // jitter — rozprasza ruch await new Promise(r => setTimeout(r, delay)); } } } // Fallback: spróbuj głównego modelu, potem zapasowego export async function completeWithFallback(prompt: string) { try { return await withRetry(() => callAnthropic(prompt)); } catch { return await withRetry(() => callOpenAI(prompt)); } } declare function callAnthropic(p: string): Promise; declare function callOpenAI(p: string): Promise;

Koszty: tokeny × cena

Ceny podaje się za milion tokenów (MTok), osobno dla wejścia i wyjścia. Wpisz realne wartości ze swojego projektu i cennika wybranego modelu.

Trzy dźwignie optymalizacji kosztów

⚡ Prompt caching

Stały prefiks (system prompt, definicje narzędzi, duży dokument) jest cache'owany po stronie dostawcy. Kolejne wywołania czytają go wielokrotnie taniej i szybciej. W Anthropic oznaczasz punkt cache cache_control, OpenAI cache'uje długie prefiksy automatycznie.

📦 Batch API

Zadania niewymagające natychmiastowej odpowiedzi (nocne przetwarzanie, ewaluacje) wysyłasz paczką — wynik w ciągu do 24 h, zwykle za ok. połowę ceny.

✂️ Mniej tokenów

Mniejszy model tam, gdzie wystarcza, krótsze odpowiedzi (format!), przycinanie historii i wyników narzędzi, RAG zamiast całych dokumentów.

const res = await client.messages.create({ model: "claude-sonnet-5-5", max_tokens: 1000, system: [ { type: "text", text: HUGE_PRODUCT_MANUAL, // np. 40k tokenów, identyczne w każdym wywołaniu cache_control: { type: "ephemeral" }, // wszystko DO tego miejsca trafia do cache }, ], messages: [{ role: "user", content: question }], // zmienna część — PO prefiksie }); console.log(res.usage.cache_creation_input_tokens, res.usage.cache_read_input_tokens);
Cache działa tylko na identycznym prefiksieDowolna zmiana na początku (np. data i godzina wstawiona do system promptu) unieważnia cache. Zmienne elementy umieszczaj na końcu kontekstu.
Bezpieczeństwo klucza APINigdy nie umieszczaj klucza w kodzie frontendu ani w repozytorium. Wywołania zawsze przez Twój backend, z własnym limitem per użytkownik — inaczej ktoś wyda Twój budżet w jedną noc.
Twój endpoint zwraca czasem niepoprawny JSON, a w logach widać stop_reason: "max_tokens". Co się dzieje?
Stop reason „max_tokens” oznacza ucięcie. Zwiększ limit, skróć oczekiwany output albo podziel zadanie. I zawsze sprawdzaj stop_reason przed parsowaniem.

🧪 Ćwiczenia praktyczne

Najpierw poczuj API na żywo, potem napisz elementy, które w produkcji otaczają każde wywołanie: parser strumienia, ponawianie, raport kosztów i walidację wyniku.
