Co AI Engineer faktycznie robi

🧩 Integruje modele

Wybiera model pod zadanie, obsługuje API, streaming, retry, limity, koszty.

📚 Podłącza wiedzę

Buduje RAG: chunking dokumentów, embeddingi, wyszukiwanie, cytowania źródeł.

🛠️ Daje modelowi narzędzia

Tool calling, agenci, serwery MCP — model wykonuje akcje w systemach.

📏 Mierzy jakość

Zestawy testowe (evals), LLM-as-judge, regresje po zmianie promptu lub modelu.

🛡️ Zabezpiecza

Prompt injection, wycieki danych, moderacja, PII, uprawnienia narzędzi.

📈 Utrzymuje na produkcji

Tracing, monitoring kosztów i latencji, cache, fallbacki, wersjonowanie promptów.

Anatomia aplikacji opartej o LLM

Praktycznie każda aplikacja AI, którą zbudujesz, składa się z tych samych warstw. Kliknij ▶ Auto albo przechodź krokami, żeby zobaczyć, jak przepływa jedno zapytanie użytkownika.

Przepływ zapytania przez warstwy aplikacji
  1. Użytkownik wpisuje pytanie w UI. Odpowiedź będzie streamowana token po tokenie — UI musi to obsłużyć.
  2. Backend przyjmuje żądanie (nigdy nie wołaj API LLM z przeglądarki — wyciekłby klucz). Guardrails wejścia: limity długości, moderacja, wykrywanie prompt injection, rate limiting per użytkownik.
  3. Warstwa orkiestracji buduje kontekst: system prompt + historia rozmowy + dokumenty z RAG + definicje narzędzi. To tutaj dzieje się większość „inżynierii AI”.
  4. Kontekst trafia do modelu. Model generuje odpowiedź albo prosi o wywołanie narzędzia.
  5. Jeśli model poprosił o narzędzie (np. „sprawdź status zamówienia”), backend je wykonuje i odsyła wynik do modelu. Ta pętla to właśnie agent.
  6. Guardrails wyjścia: walidacja formatu (np. JSON zgodny ze schematem), filtrowanie PII, sprawdzenie, czy odpowiedź cytuje źródła.
  7. Odpowiedź wraca do UI. Każdy krok był zalogowany w systemie observability, więc możesz policzyć koszt, czas i jakość.

Kiedy NIE używać LLM

Dojrzały AI Engineer często mówi „tu nie potrzebujemy modelu”. LLM jest drogi, wolny (setki ms – sekundy), niedeterministyczny i może się mylić. Klasyczny kod wygrywa, gdy:

❌ Zły kandydat

Walidacja e-maila, obliczenia finansowe, sortowanie, reguły biznesowe z jasną specyfikacją, wszystko, co wymaga 100% powtarzalności, operacje wymagające <50 ms.

✅ Dobry kandydat

Rozumienie języka naturalnego, streszczanie, ekstrakcja danych z nieustrukturyzowanego tekstu, klasyfikacja z niejasnymi granicami, generowanie treści, wyszukiwanie semantyczne, asystenci.

Reguła kciukaJeśli potrafisz napisać test jednostkowy z jednym poprawnym wynikiem i prostą funkcją, która go zawsze przechodzi — napisz funkcję. LLM ma sens tam, gdzie „poprawnych” odpowiedzi jest wiele, a reguły trudno spisać.
