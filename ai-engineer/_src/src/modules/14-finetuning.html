Fine-tuning: kiedy i jak dostrajać modele

Fine-tuning to potężne, ale często nadużywane narzędzie. Dowiesz się, kiedy ma sens, jak przygotować dane, czym jest LoRA i jak przeprowadzić trening przez API oraz lokalnie.

drzewo decyzjiSFT, LoRA, DPOprzygotowanie danychdestylacjaewaluacja przed/po
TL;DR Fine-tuning zmienia zachowanie modelu (format, styl, wąska umiejętność), a nie jego wiedzę. Najpierw wyciśnij maksimum z promptu i RAG. Najczęstszy dobry powód do fine-tuningu w produkcji: tańszy i szybszy mały model, który w jednym konkretnym zadaniu dorównuje dużemu.

Drzewo decyzji

✅ Dobre powody

Spójny format/styl, którego nie da się stabilnie uzyskać promptem. Krótszy prompt (instrukcje „wtopione” w model) → niższy koszt. Mały model dorównujący dużemu w wąskim zadaniu (klasyfikacja, ekstrakcja, routing). Specjalistyczny żargon i konwencje.

❌ Złe powody

„Chcę, żeby model znał naszą dokumentację” → RAG. „Model halucynuje” → RAG, cytaty, weryfikacja. „Chcę aktualnych danych” → narzędzia. „Nie chce mi się pisać promptu” → fine-tuning wymaga dużo więcej pracy.

Rodzaje dostrajania

MetodaDaneDo czego

LoRA — jak to działa

Dane — to one decydują

  • Jakość > ilość. 200 perfekcyjnych przykładów pokonuje 5000 przypadkowych. Model nauczy się także błędów.
  • Reprezentatywność: rozkład przykładów jak w produkcji, w tym trudne i nietypowe przypadki.
  • Ten sam format co na produkcji (ten sam system prompt, struktura wejścia).
  • Podział: zbiór treningowy, walidacyjny (dobór hiperparametrów) i testowy, którego model nigdy nie widział.
  • Źródła: ręcznie oznaczone dane, poprawione odpowiedzi dużego modelu, logi produkcyjne (po anonimizacji i zgodnie z prawem).

Wzorzec: destylacja (duży uczy małego)

1. Duży model + najlepszy prompt→2. Generuj odpowiedzi na tysiące realnych wejść→3. Filtruj (evale, człowiek)→4. SFT małego modelu→5. Porównaj na zbiorze testowym

Efekt: jakość bliska dużemu modelowi w tym jednym zadaniu, przy kilkukrotnie niższym koszcie i latencji. Sprawdź warunki licencji dostawcy dotyczące używania wyników jego modeli do trenowania innych modeli.

Fine-tuning przez API (bez GPU)

import OpenAI from "openai"; import fs from "node:fs"; const openai = new OpenAI(); // 1. upload danych const train = await openai.files.create({ file: fs.createReadStream("train.jsonl"), purpose: "fine-tune" }); const val = await openai.files.create({ file: fs.createReadStream("val.jsonl"), purpose: "fine-tune" }); // 2. zadanie treningowe const job = await openai.fineTuning.jobs.create({ model: "", training_file: train.id, validation_file: val.id, suffix: "ticket-classifier", }); // 3. sprawdzaj status (albo webhook) let status = job.status; while (!["succeeded", "failed", "cancelled"].includes(status)) { await new Promise(r => setTimeout(r, 30_000)); const j = await openai.fineTuning.jobs.retrieve(job.id); status = j.status; console.log(status, j.fine_tuned_model ?? ""); } // 4. wynikowy model wołasz jak każdy inny, podając jego ID (ft:...)

Fine-tuning przez API oferuje część dostawców (m.in. OpenAI, Google Vertex, Amazon Bedrock dla wybranych modeli, w tym niektórych modeli Claude). Lista modeli i metod zmienia się — sprawdzaj dokumentację.

LoRA na modelu open-source (Python)

# pip install transformers trl peft datasets accelerate bitsandbytes from datasets import load_dataset from peft import LoraConfig from trl import SFTTrainer, SFTConfig dataset = load_dataset("json", data_files={"train": "train.jsonl", "test": "val.jsonl"}) peft_config = LoraConfig( r=16, # rank — rozmiar adaptera lora_alpha=32, # skala poprawki lora_dropout=0.05, target_modules="all-linear", task_type="CAUSAL_LM", ) trainer = SFTTrainer( model="Qwen/Qwen3-1.7B", # mały model — szybkie eksperymenty train_dataset=dataset["train"], # kolumna "messages" → chat template stosowany automatycznie eval_dataset=dataset["test"], peft_config=peft_config, args=SFTConfig( output_dir="out/ticket-lora", num_train_epochs=3, per_device_train_batch_size=4, learning_rate=2e-4, eval_strategy="epoch", logging_steps=10, ), ) trainer.train() trainer.save_model("out/ticket-lora") # zapisuje tylko adapter (kilka-kilkadziesiąt MB)

Jak czytać krzywe uczenia

Ewaluacja: przed i po

  • Baseline: model bazowy + najlepszy prompt na zbiorze testowym
  • Model po fine-tuningu na tym samym zbiorze testowym
  • Sprawdzenie, czy model nie stracił ogólnych umiejętności (catastrophic forgetting) — kilka zadań spoza domeny
  • Koszt i latencja na realnym ruchu, w tym koszt hostingu modelu dostrojonego
  • Plan ponownego treningu, gdy dane lub model bazowy się zmienią
Klient chce, żeby chatbot „znał” 3000 stron dokumentacji produktu, która zmienia się co tydzień. Co rekomendujesz?
Wiedza, która się zmienia i wymaga cytatów, to klasyczny przypadek RAG. Fine-tuning słabo wgrywa fakty i wymagałby ciągłego ponawiania treningu.
