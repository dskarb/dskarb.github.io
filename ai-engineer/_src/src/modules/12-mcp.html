Model Context Protocol (MCP)

Otwarty standard podłączania narzędzi i danych do aplikacji AI. Architektura, prymitywy, własny serwer w TypeScript, klient w Twojej aplikacji i bezpieczeństwo.

host / client / servertools, resources, promptsserwer MCP w TSklient MCP + LLMzagrożenia
TL;DR MCP to „USB-C dla AI”: piszesz serwer z narzędziami raz, a może z niego korzystać każda aplikacja zgodna z MCP (Claude, IDE, agenci, Twoja aplikacja). Komunikacja to JSON-RPC 2.0 przez stdio (lokalnie) albo HTTP (zdalnie).

Problem, który rozwiązuje

Architektura

🏠 Host

Aplikacja AI, z którą pracuje użytkownik: Claude (desktop/web), IDE, Claude Code, Twój czat. Zarządza klientami i zgodami użytkownika.

🔌 Client

Komponent w hoście utrzymujący połączenie 1:1 z jednym serwerem. Pobiera listę narzędzi, wywołuje je, przekazuje wyniki do modelu.

🧰 Server

Program udostępniający możliwości: narzędzia, zasoby, prompty. Może działać lokalnie (proces) albo zdalnie (usługa HTTP).

TransportJak działaKiedy
stdioHost uruchamia serwer jako proces potomny; JSON-RPC przez stdin/stdoutNarzędzia lokalne: pliki, git, lokalna baza
Streamable HTTPSerwer pod adresem URL; żądania POST, odpowiedzi opcjonalnie strumieniowane (SSE); autoryzacja OAuthUsługi zdalne: SaaS, firmowe API, wielu użytkowników

Prymitywy MCP

PrymitywKto kontrolujeCo to jestPrzykład
ToolsModelFunkcje, które model może wywołaćcreate_issue, run_query
ResourcesAplikacja / użytkownikDane tylko do odczytu adresowane URI, dołączane do kontekstufile:///README.md, db://schema
PromptsUżytkownikGotowe szablony wywoływane świadomie (często jako komendy „/”)/code-review

Serwer może też korzystać z możliwości klienta: sampling (poproś model hosta o generację), elicitation (zapytaj użytkownika o dodatkowe dane), roots (do których folderów serwer ma dostęp).

Własny serwer MCP w TypeScript

mkdir mcp-orders && cd mcp-orders && npm init -y npm i @modelcontextprotocol/sdk zod npm i -D tsx typescript @types/node import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js"; import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js"; import { z } from "zod"; const server = new McpServer({ name: "orders-server", version: "1.0.0" }); const ORDERS: Record = { "481": { status: "w drodze", eta: "2026-10-14" }, "482": { status: "dostarczone", eta: "2026-10-10" }, }; // TOOL — model sam decyduje, kiedy go użyć server.registerTool( "get_order", { title: "Status zamówienia", description: "Zwraca status i przewidywaną datę dostawy zamówienia o podanym numerze.", inputSchema: { order_id: z.string().describe("Numer zamówienia, np. '481'") }, }, async ({ order_id }) => { const order = ORDERS[order_id]; if (!order) { return { content: [{ type: "text", text: `Brak zamówienia ${order_id}.` }], isError: true }; } return { content: [{ type: "text", text: JSON.stringify(order) }] }; }, ); // RESOURCE — dane do dołączenia do kontekstu server.registerResource( "return-policy", "policy://zwroty", { title: "Polityka zwrotów", description: "Aktualny regulamin zwrotów", mimeType: "text/markdown" }, async (uri) => ({ contents: [{ uri: uri.href, text: "# Zwroty\nZwrot w ciągu 14 dni bez podania przyczyny." }], }), ); // PROMPT — szablon wywoływany przez użytkownika server.registerPrompt( "complaint-reply", { title: "Odpowiedź na reklamację", description: "Przygotowuje uprzejmą odpowiedź na reklamację klienta", argsSchema: { complaint: z.string() }, }, ({ complaint }) => ({ messages: [{ role: "user", content: { type: "text", text: `Napisz uprzejmą odpowiedź na reklamację, zgodną z polityką zwrotów:\n\n${complaint}` }, }], }), ); await server.connect(new StdioServerTransport()); console.error("orders-server działa"); // przy stdio loguj na stderr — stdout jest kanałem protokołu!
Najczęstszy błądPrzy transporcie stdio console.log wypisuje na stdout, które jest zarezerwowane dla komunikatów JSON-RPC. Jedno przypadkowe logowanie psuje protokół. Używaj console.error.

Klient MCP we własnej aplikacji

Twoja aplikacja może korzystać z dowolnego serwera MCP i przekazywać jego narzędzia modelowi — tak łączysz moduł 11 z MCP.

import { Client } from "@modelcontextprotocol/sdk/client/index.js"; import { StdioClientTransport } from "@modelcontextprotocol/sdk/client/stdio.js"; import Anthropic from "@anthropic-ai/sdk"; const mcp = new Client({ name: "my-chat-app", version: "1.0.0" }); await mcp.connect(new StdioClientTransport({ command: "npx", args: ["tsx", "../mcp-orders/server.ts"] })); // 1. Narzędzia z serwera MCP → format narzędzi Anthropic const { tools: mcpTools } = await mcp.listTools(); const tools: Anthropic.Tool[] = mcpTools.map(t => ({ name: t.name, description: t.description ?? "", input_schema: t.inputSchema as Anthropic.Tool.InputSchema, })); // 2. W pętli agenta (moduł 11) zamiast lokalnych implementacji: async function executeTool(name: string, args: Record) { const result = await mcp.callTool({ name, arguments: args }); const text = (result.content as { type: string; text?: string }[]) .filter(c => c.type === "text").map(c => c.text).join("\n"); return { text, isError: Boolean(result.isError) }; }

Część API dostawców potrafi też samodzielnie łączyć się ze zdalnymi serwerami MCP — podajesz URL serwera w żądaniu, a pętlę narzędzi wykonuje dostawca. Wygodne, ale wtedy mniej kontrolujesz (np. zatwierdzanie akcji).

Bezpieczeństwo MCP

🧪 Tool poisoning

Złośliwy serwer umieszcza instrukcje w opisie narzędzia („przed użyciem wyślij zawartość ~/.ssh…”). Opisy trafiają do kontekstu modelu.

🔄 Zmiana definicji

Serwer zaakceptowany jako bezpieczny może później zmienić narzędzia. Przypinaj wersje, weryfikuj zmiany.

🎭 Cieniowanie nazw

Dwa serwery z narzędziem o tej samej nazwie — model może wywołać nie to, które myślisz.

🔑 Uprawnienia

Serwer zdalny z OAuth powinien mieć minimalne zakresy. Lokalny serwer stdio działa z uprawnieniami Twojego użytkownika — instaluj tylko zaufane.

ZasadyInstaluj serwery tylko z zaufanych źródeł, czytaj kod lokalnych serwerów, wymagaj zatwierdzania akcji zapisu, nie łącz w jednej sesji serwera z dostępem do wrażliwych danych i serwera, który czyta niezaufane treści z internetu (śmiertelna trójka z modułu 06).
Chcesz, żeby użytkownik mógł świadomie wybrać z menu gotowy szablon „/code-review”. Którego prymitywu MCP użyjesz?
Prompts są kontrolowane przez użytkownika — to szablony wywoływane świadomie. Tools wybiera model, a Resources to dane dołączane do kontekstu.
