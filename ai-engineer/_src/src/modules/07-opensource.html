Biblioteka transformers (Python)

Najszybszy start to pipeline — jedna linijka na typowe zadanie. Model pobierze się automatycznie przy pierwszym uruchomieniu.

from transformers import pipeline # Klasyfikacja zero-shot: kategorie podajesz w locie, bez treningu clf = pipeline("zero-shot-classification", model="MoritzLaurer/mDeBERTa-v3-base-mnli-xnli") print(clf("Paczka przyszła uszkodzona i chcę zwrot pieniędzy", candidate_labels=["reklamacja", "pytanie o produkt", "pochwała"])) # {'labels': ['reklamacja', ...], 'scores': [0.94, ...]} # Rozpoznawanie nazw własnych (NER) ner = pipeline("ner", model="Babelscape/wikineural-multilingual-ner", aggregation_strategy="simple") print(ner("Jan Kowalski pracuje w Rzeszowie dla firmy Asseco.")) # Transkrypcja mowy asr = pipeline("automatic-speech-recognition", model="openai/whisper-small") print(asr("nagranie.mp3")["text"])

Generowanie tekstu lokalnym LLM-em

from transformers import AutoTokenizer, AutoModelForCausalLM import torch model_id = "Qwen/Qwen3-1.7B" # mały model, zadziała nawet na CPU (wolno) tok = AutoTokenizer.from_pretrained(model_id) model = AutoModelForCausalLM.from_pretrained(model_id, torch_dtype="auto", device_map="auto") messages = [ {"role": "system", "content": "Odpowiadaj krótko po polsku."}, {"role": "user", "content": "Czym jest embedding?"}, ] # chat template zamienia listę wiadomości na format, na którym model był trenowany inputs = tok.apply_chat_template(messages, add_generation_prompt=True, return_tensors="pt").to(model.device) with torch.no_grad(): out = model.generate(inputs, max_new_tokens=200, temperature=0.7, do_sample=True) print(tok.decode(out[0][inputs.shape[-1]:], skip_special_tokens=True))
Chat templateKażda rodzina modeli ma własny format specjalnych tokenów oddzielających role (system/user/assistant). Zawsze używaj apply_chat_template zamiast ręcznego sklejania — zły format drastycznie obniża jakość.

transformers.js — AI w przeglądarce i Node

Dla frontendowca to perełka: te same modele (w formacie ONNX) działają w przeglądarce przez WebAssembly/WebGPU. Zero kosztów serwera, dane nie opuszczają urządzenia.

import { pipeline } from "@huggingface/transformers"; // Model (~25 MB) pobiera się raz i zostaje w cache przeglądarki const extractor = await pipeline("feature-extraction", "Xenova/all-MiniLM-L6-v2"); const output = await extractor(["Jak zresetować hasło?", "Nie pamiętam hasła do konta"], { pooling: "mean", normalize: true, }); const [a, b] = output.tolist() as number[][]; const cosine = a.reduce((s, x, i) => s + x * b[i], 0); // znormalizowane → iloczyn skalarny = cosine console.log(cosine.toFixed(3)); // wysoka wartość = podobne znaczenie // Analiza sentymentu w przeglądarce const sentiment = await pipeline("sentiment-analysis"); console.log(await sentiment("I love this product!"));

Zastosowania: wyszukiwanie semantyczne w aplikacji offline, filtrowanie treści przed wysłaniem na serwer, podpowiedzi w edytorze, rozpoznawanie mowy w przeglądarce.

Ollama — LLM na laptopie w 2 minuty

# instalacja: ollama.com (macOS/Windows) lub: curl -fsSL https://ollama.com/install.sh | sh ollama pull llama3.2 # pobierz model (nazwy w bibliotece ollama.com) ollama run llama3.2 # interaktywny czat w terminalu ollama pull nomic-embed-text # model embeddingów ollama list # pobrane modele ollama ps # co jest załadowane do pamięci // 1) natywne REST API Ollamy const res = await fetch("http://localhost:11434/api/chat", { method: "POST", body: JSON.stringify({ model: "llama3.2", messages: [{ role: "user", content: "Podaj 3 zastosowania RAG." }], stream: false, options: { temperature: 0.3 }, }), }); const data = await res.json(); console.log(data.message.content); // 2) embeddingi const emb = await fetch("http://localhost:11434/api/embed", { method: "POST", body: JSON.stringify({ model: "nomic-embed-text", input: ["tekst 1", "tekst 2"] }), }).then(r => r.json()); console.log(emb.embeddings.length, emb.embeddings[0].length); // 3) endpoint zgodny z OpenAI — ten sam kod co dla chmury import OpenAI from "openai"; const local = new OpenAI({ baseURL: "http://localhost:11434/v1", apiKey: "ollama" }); const r = await local.chat.completions.create({ model: "llama3.2", messages: [{ role: "user", content: "Cześć!" }], }); console.log(r.choices[0].message.content);
Workflow deweloperaLokalny model przez endpoint zgodny z OpenAI to świetne środowisko deweloperskie i testowe: darmowe, offline, bez limitów. Na produkcji podmieniasz baseURL i model na chmurowy.

Kwantyzacja i pamięć GPU

Każdy parametr modelu to liczba. W pełnej precyzji treningowej (FP16/BF16) zajmuje 2 bajty. Kwantyzacja zapisuje wagi na mniejszej liczbie bitów (8, 4, nawet 2–3). Model 8B w FP16 to ~16 GB, w 4 bitach ~5 GB.

Kalkulator pamięci (VRAM)

Wzór: wagi = parametry × bity / 8; KV cache to zgrubne przybliżenie dla modeli z grouped-query attention w FP16 (realnie zależy od architektury); +15% na narzut. Do decyzji zakupowych testuj na realnym sprzęcie.

Kiedy self-hosting ma sens

✅ Tak

Dane nie mogą opuścić infrastruktury (medycyna, prawo, sektor publiczny). Duży, stały wolumen prostych zadań. Potrzeba zamrożonej wersji modelu. Fine-tuning pod wąskie zadanie. Działanie offline / na urządzeniu.

❌ Raczej nie

Mały lub zmienny ruch (GPU stoi bezczynnie, a płacisz). Potrzebujesz najwyższej jakości. Brak kompetencji DevOps/MLOps w zespole. Start projektu — najpierw udowodnij wartość na API.

Masz kartę graficzną z 12 GB VRAM. Który wariant modelu 14B prawdopodobnie zmieścisz z kontekstem 8k?
14 mld × ~4.5 bita / 8 ≈ 7,9 GB na wagi. Z KV cache i narzutem mieści się w 12 GB. Sprawdź w kalkulatorze powyżej.

🧪 Ćwiczenia praktyczne

Policz wymagania sprzętowe przed zakupem GPU. Jeśli chcesz pracować z modelem lokalnie, skonfiguruj Ollamę według instrukcji w sekcji Laboratorium: jak zacząć — wszystkie laboratoria działają też na niej.
