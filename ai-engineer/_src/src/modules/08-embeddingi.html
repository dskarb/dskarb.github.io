Embeddingi — znaczenie zapisane w liczbach

Fundament wyszukiwania semantycznego, RAG, rekomendacji i klasyfikacji. Zrozumiesz intuicję, metryki podobieństwa i napiszesz wyszukiwarkę od zera.

TL;DR Model embeddingów zamienia tekst (lub obraz) na wektor liczb o stałej długości, np. 1536. Teksty o podobnym znaczeniu dają wektory bliskie sobie — nawet jeśli nie mają wspólnych słów. „Jak zresetować hasło?” i „Nie pamiętam hasła do konta” będą obok siebie.

Intuicja: mapa znaczeń

Wyobraź sobie mapę, na której każde słowo ma współrzędne. Prawdziwe embeddingi mają setki lub tysiące wymiarów, ale zasada jest ta sama co w 2D. Kliknij dowolny punkt, aby uczynić go zapytaniem — zobaczysz najbliższych sąsiadów według cosine similarity.

Przestrzeń embeddingów 2D

Zwróć uwagę na „Apple (firma)” — leży pomiędzy owocami a technologią. Prawdziwe modele embeddingów korzystają z kontekstu całego zdania, więc „Apple wypuściło nowy telefon” trafi bliżej technologii, a „upiekłam szarlotkę z apple” bliżej owoców.

Słynny przykładW klasycznych embeddingach słów działała arytmetyka znaczeń: wektor(„król”) − wektor(„mężczyzna”) + wektor(„kobieta”) ≈ wektor(„królowa”). Kierunki w przestrzeni kodują relacje (płeć, liczba mnoga, czas). Współczesne modele zdań są bogatsze, ale idea „znaczenie = położenie” zostaje.

Miary podobieństwa

cosine(A, B) = (A · B) / (‖A‖ × ‖B‖) zakres: −1 … 1 (1 = ten sam kierunek)
dot(A, B) = Σ aᵢ·bᵢ dla wektorów znormalizowanych = cosine
euclidean(A, B) = √Σ (aᵢ − bᵢ)² 0 = identyczne
Kalkulator podobieństwa

Spróbuj: B = 1.8, 0.2, 0.6 (ten sam kierunek, dłuższy wektor) — cosine = 1, ale odległość euklidesowa duża. Cosine patrzy tylko na kierunek.

W praktyceWiększość modeli embeddingów zwraca wektory znormalizowane (długość 1). Wtedy cosine = iloczyn skalarny, a ranking według euklidesa jest identyczny. Używaj metryki zalecanej w dokumentacji modelu — zwykle cosine.

Do czego służą embeddingi

🔎 Wyszukiwanie semantyczne

Szukanie po znaczeniu, nie słowach kluczowych. Serce RAG.

🎯 Rekomendacje

„Podobne produkty/artykuły”: najbliżsi sąsiedzi tego, co użytkownik oglądał.

🏷️ Klasyfikacja

Najbliższy centroid kategorii albo lekki klasyfikator na wektorach — tanio i szybko.

🧩 Klastrowanie

Grupowanie tysięcy opinii lub zgłoszeń w tematy (k-means, HDBSCAN).

🚨 Wykrywanie anomalii

Tekst daleko od wszystkich znanych klastrów = nietypowy (oszustwo, nowy problem).

♻️ Deduplikacja

Wykrywanie niemal identycznych dokumentów lub pytań (cosine > próg).

Wyszukiwarka semantyczna od zera

import OpenAI from "openai"; const openai = new OpenAI(); const EMBED_MODEL = "text-embedding-3-small"; // 1536 wymiarów, tani async function embed(texts: string[]): Promise { // API przyjmuje wiele tekstów naraz — zawsze batchuj const res = await openai.embeddings.create({ model: EMBED_MODEL, input: texts }); return res.data.map(d => d.embedding); } const dot = (a: number[], b: number[]) => a.reduce((s, x, i) => s + x * b[i], 0); // wektory OpenAI są znormalizowane → dot = cosine const docs = [ "Aby zresetować hasło, kliknij 'Nie pamiętam hasła' na stronie logowania.", "Zwrot towaru jest możliwy w ciągu 14 dni od otrzymania przesyłki.", "Wysyłka kurierem trwa zazwyczaj 1–2 dni robocze.", "Fakturę VAT znajdziesz w zakładce Moje zamówienia.", "Płatność BLIK jest księgowana natychmiast.", ]; // Indeksowanie — raz (w prawdziwym systemie: zapis do bazy wektorowej) const docVectors = await embed(docs); export async function search(query: string, k = 2) { const [q] = await embed([query]); return docs .map((text, i) => ({ text, score: dot(q, docVectors[i]) })) .sort((a, b) => b.score - a.score) .slice(0, k); } console.log(await search("nie mogę się zalogować, zapomniałem hasła")); console.log(await search("ile czeka się na paczkę?")); console.log(await search("chcę oddać buty"));

Zauważ: zapytanie „chcę oddać buty” nie ma żadnego wspólnego słowa z „Zwrot towaru jest możliwy…”, a i tak go znajdzie. Tego nie zrobi klasyczne wyszukiwanie po słowach.

To samo w Pythonie, lokalnie i za darmo

from sentence_transformers import SentenceTransformer import numpy as np # Model wielojęzyczny — dobrze radzi sobie z polskim model = SentenceTransformer("intfloat/multilingual-e5-base") docs = ["Zwrot towaru w ciągu 14 dni.", "Wysyłka trwa 1-2 dni.", "Reset hasła na stronie logowania."] # modele E5 wymagają prefiksów: "passage: " dla dokumentów i "query: " dla zapytań doc_emb = model.encode([f"passage: {d}" for d in docs], normalize_embeddings=True) q_emb = model.encode(["query: jak oddać zamówienie?"], normalize_embeddings=True) scores = (q_emb @ doc_emb.T)[0] # iloczyn macierzowy = cosine dla wszystkich naraz for i in np.argsort(-scores): print(f"{scores[i]:.3f} {docs[i]}")

  • Ranking MTEB (Massive Text Embedding Benchmark) porównuje modele na wielu zadaniach — istnieje też wariant z polskimi zadaniami. Jak zawsze: ostatecznie testuj na własnych danych.
  • Więcej wymiarów = zwykle lepsza jakość, ale więcej pamięci i wolniejsze wyszukiwanie. 1 mln wektorów × 1536 float32 ≈ 6 GB.
  • Matryoshka embeddings: część modeli jest trenowana tak, że pierwsze N wymiarów samo w sobie jest dobrym embeddingiem. Możesz przyciąć 3072 → 512 i stracić niewiele jakości.
  • Modele asymetryczne rozróżniają zapytanie (krótkie) i dokument (długi) — prefiksy lub parametr typu wejścia. Pominięcie tego obniża jakość.
Złota zasadaZapytania i dokumenty muszą być zembeddowane tym samym modelem (i tą samą wersją). Wektory z różnych modeli żyją w różnych przestrzeniach — porównywanie ich nie ma sensu. Zmiana modelu = ponowne zembeddowanie całej bazy, więc zapisuj nazwę modelu przy każdym wektorze.

Klasyfikacja embeddingami (bez LLM)

// Kilka przykładów na kategorię → średni wektor (centroid) → najbliższy centroid wygrywa. // Koszt: ułamek centa za tysiące klasyfikacji, latencja kilkadziesiąt ms. const labeled: Record = { dostawa: ["gdzie jest moja paczka", "kurier nie przyjechał", "kiedy dostanę zamówienie"], zwrot: ["chcę oddać produkt", "jak zwrócić towar", "zwrot pieniędzy za buty"], platnosc: ["dwa razy pobrało mi pieniądze", "nie przeszła płatność BLIK", "faktura się nie zgadza"], }; const centroids: Record = {}; for (const [label, examples] of Object.entries(labeled)) { const vecs = await embed(examples); const mean = vecs[0].map((_, d) => vecs.reduce((s, v) => s + v[d], 0) / vecs.length); const norm = Math.hypot(...mean); centroids[label] = mean.map(x => x / norm); // normalizacja po uśrednieniu } export async function classify(text: string) { const [v] = await embed([text]); const scored = Object.entries(centroids).map(([label, c]) => ({ label, score: dot(v, c) })); scored.sort((a, b) => b.score - a.score); // niska pewność → przekaż do LLM lub człowieka return scored[0].score < 0.3 ? { label: "niepewne", scored } : { label: scored[0].label, scored }; } declare function embed(t: string[]): Promise; declare function dot(a: number[], b: number[]): number;

Próg 0.3 jest przykładowy — rozkład wartości cosine zależy od modelu. Ustal próg na zbiorze walidacyjnym.
