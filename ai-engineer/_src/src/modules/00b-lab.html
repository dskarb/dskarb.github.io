Laboratorium: nauka na realnych przypadkach

W każdym module znajdziesz ćwiczenia osadzone w konkretnych sytuacjach biznesowych: sklep internetowy, biuro rachunkowe, salon kosmetyczny, kawiarnia, przychodnia. Ta sekcja wyjaśnia, jak z nich korzystać, i pokazuje Twoje postępy.

Dwa rodzaje ćwiczeń

Zadania z kodem

Piszesz funkcję w JavaScript bezpośrednio na stronie, a testy sprawdzają ją od razu (kod działa w izolowanym Web Workerze z limitem czasu). To fragmenty prawdziwych systemów AI: parser strumienia SSE, retry z backoffem, walidator faktur, maskowanie PESEL-u, BM25, chunker, pętla agenta, serwer MCP, raport evali.

Nie potrzebujesz klucza API ani internetu. Twój kod zapisuje się w przeglądarce.

Laboratoria na żywym modelu

Pracujesz z prawdziwym LLM-em: iterujesz prompt i mierzysz trafność, atakujesz własnego bota, budujesz RAG i sterujesz każdym etapem, obserwujesz agenta krok po kroku, kalibrujesz sędziego LLM.

Potrzebujesz dostawcy AI: klucza API (Anthropic, OpenAI, OpenRouter…) albo darmowej Ollamy na swoim komputerze. Konfiguracja: przycisk 🔑 AI u góry strony.

Postępy

Konfiguracja dostawcy AI

Opcja A: klucz API (najlepsza jakość)

  1. W konsoli dostawcy utwórz osobny klucz tylko do nauki.
  2. Ustaw miesięczny limit wydatków, np. 5 $.
  3. Kliknij 🔑 AI, wybierz dostawcę, wklej klucz, wpisz ceny z cennika (wtedy zobaczysz koszty), kliknij „Test połączenia”.

Do labów wystarczy tani model (np. Haiku albo mini). Pełne przejście wszystkich laboratoriów to zwykle kilkaset wywołań po kilkaset–kilka tysięcy tokenów, czyli przy tanim modelu koszt rzędu centów–pojedynczych dolarów. Policz to sam w labie „Wywołania API”.

Opcja B: Ollama (za darmo, lokalnie)

Model działa na Twoim komputerze. Musisz pozwolić tej stronie łączyć się z Ollamą (CORS):

Jakość i obsługa narzędzi zależą od modelu. Do agenta wybierz model z obsługą tool callingu (np. qwen3), do labu z paragonem model z vision.

# modele: czat z narzędziami + embeddingi wielojęzyczne ollama pull qwen3:8b ollama pull bge-m3 # Linux / macOS (terminal) — zatrzymaj wcześniej działającą aplikację Ollama OLLAMA_ORIGINS="https://dskarb.github.io" ollama serve # macOS, gdy używasz aplikacji Ollama z paska menu: launchctl setenv OLLAMA_ORIGINS "https://dskarb.github.io" # potem uruchom ponownie aplikację # Windows (PowerShell), potem uruchom ponownie Ollamę: setx OLLAMA_ORIGINS "https://dskarb.github.io"

W 🔑 AI wybierz „Ollama”, wpisz model (np. qwen3:8b) i model embeddingów (bge-m3). Przeglądarka może zapytać o zgodę na dostęp do urządzeń w sieci lokalnej — zezwól, bo strona łączy się z localhost.

Dlaczego tu wolno wołać API z przeglądarki, a w produkcji nieW module 04 jest zasada: klucz API nigdy nie trafia do frontendu. Laboratorium to wyjątek, który ma sens tylko dlatego, że to Twój klucz, w Twojej przeglądarce, na stronie do nauki. W aplikacji dla użytkowników każdy mógłby go odczytać z narzędzi deweloperskich. Anthropic wymaga nawet specjalnego nagłówka anthropic-dangerous-direct-browser-access, żeby takie wywołanie było świadomą decyzją.

Jak pracować z ćwiczeniami

1. Przewiduj

Zanim uruchomisz lab, zapisz, jakiego wyniku się spodziewasz. Rozjazd między przewidywaniem a wynikiem to najlepszy moment nauki.

2. Zmieniaj jedną rzecz

Jedna zmiana promptu lub parametru → jeden pomiar. Historia uruchomień w labach pomaga porównywać.

3. Przenieś do repo

Rozwiązane zadania z kodem przepisz do swojego ai-playground w TypeScript (dodaj typy). Z kilku zrobisz bibliotekę: retry, parser SSE, walidator, BM25, RRF, chunker, pętla agenta.

4. Zrób z tego projekt

Laby to prototypy projektów z modułu 17. Lab RAG + zadania z modułu 10 = szkielet Projektu 2; lab agenta + zadania z modułu 11 = Projekt 3.
